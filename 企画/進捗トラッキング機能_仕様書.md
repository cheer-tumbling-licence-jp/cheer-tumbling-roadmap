## 1. 目的とゴール

ロードマップを「みんなの参考資料」から「**自分（自分の子・自分のチーム）の成長記録**」に変える。

- 選手ごとに、約80技の習得状況を記録・可視化する。
- 習得の記録が**日々溜まっていく**ことで、保護者は記録への愛着を持ち、**解約しにくくなる**（＝継続課金の核）。
- 「次に何を練習すべきか」が一目で分かり、ロードマップが**行動できるツール**になる。

---

## 2. ユーザーストーリー

- **保護者**：「うちの子が今どの技まで習得したか一目で見たい。前転を習得した日を記録に残したい」
- **選手**：「次にどの技へ挑戦できるか知りたい。習得した技が増えるのが嬉しい」
- **コーチ**：「チームの選手それぞれの進捗を把握して、個別に課題を出したい」

## 3. 機能要件

### 3.1 選手（アスリート）管理
- **選手プロフィール**：名前（必須）、識別カラー（自動割当 or 選択）、絵文字アイコン（任意）、作成日。
- **人数制限**：ファミリープラン＝最大3名／コーチプラン＝無制限。
- **アクティブ選手セレクター**：「今どの選手を見ているか」を切り替えるUI。ヘッダー付近に常設。
- 選手の**追加・名前変更・削除**。
- 選手未登録の状態では進捗機能は不活性（成長記録タブで「選手を追加」を促す）。

### 3.2 技の習得ステータス
各「選手 × 技」の組に1つのステータスを持つ。**4段階**：

| ステータス | 表示 | 意味 |
|---|---|---|
| `none` | ⚪️ 未挑戦 | まだ取り組んでいない（デフォルト） |
| `practicing` | 🔵 練習中 | 練習を始めた |
| `almost` | 🟡 あと少し | できる時もあるが安定しない |
| `mastered` | 🟢 習得！ | 安定してできる |

- ステータス変更は**技詳細モーダル内のステータスUI**から行う（§4.3）。
- `mastered` に初めてした時点の日付を**習得日**として記録（成長タイムラインで使用）。
- 各記録に**メモ**（自由記入）を任意で添えられる（例：「踏み切りが課題」）。

### 3.3 ロードマップ上の可視化
- **リスト表示**：各技カードの隅に、アクティブ選手のステータスを示す**カラーリング／ドット**を表示。
- **ツリー（系譜図）表示**：各ノードをステータス色で塗る。習得が進むほど系譜図が「光っていく」体験。
- **ステータス絞り込み**（任意・v1後半）：「習得済みだけ」「練習中だけ」表示のチップ。

### 3.4 成長記録ダッシュボード（新しい4つ目のタブ）
アクティブ選手について表示：
- **全体達成率**：「全80技中 23技 習得（29%）」＋プログレスバー。
- **レベル別達成率**：ウォームアップ／基礎運動／発展技／LEVEL 1〜5 ごとの達成率バー。
- **最近の習得**：直近に `mastered` にした技と日付（数件）。
- **次に挑戦できる技**（§3.6）。
- 選手セレクターで各選手のダッシュボードに切替。

### 3.5 成長タイムライン
- 習得イベントの時系列リスト：「2026/5/16 ⭐️ 前転 習得！」。
- これが感情的フック。**記録が積み上がるほど、やめられなくなる**。

### 3.6 次に挑戦できる技
- 既存の `prereqs`（前提技）データを使い、**前提技がすべて `mastered` になっている技**を抽出して提示。
- 「いま挑戦できる技」が明確になり、ロードマップが次の一手を示すツールになる。

### 3.7 コーチ向け機能
- **v1**：コーチも「複数選手を素早く切り替えて、各選手を個別管理」できれば足りる。
- **v2**：チーム俯瞰ビュー（選手×達成率の一覧）、課題（フォーカス技）の割り当て。

### 3.8 スコープ外（v1では作らない）
- トレーニングの実施記録（技のみに絞る）。
- 選手の練習動画の添付。
- クラウド同期・複数端末共有（バックエンド必要、フェーズ4）。

## 5. データモデル

新規 localStorage キー **`cheerTumblingProgress_v1`**。
既存の技データ（`skills`）には**保存しない**（進捗は選手別データのため、技オブジェクトに混ぜると単一選手しか扱えない）。

```json
{
  "version": 1,
  "athletes": [
    {
      "id": "ath_lk3x9",
      "name": "さくら",
      "emoji": "🌸",
      "color": "#ff6fa5",
      "createdAt": "2026-05-16T09:00:00.000Z"
    }
  ],
  "activeAthleteId": "ath_lk3x9",
  "records": {
    "ath_lk3x9": {
      "forward-roll": {
        "status": "mastered",
        "achievedAt": "2026-05-16",
        "updatedAt": "2026-05-16T09:10:00.000Z",
        "memo": ""
      },
      "back-handspring": {
        "status": "practicing",
        "achievedAt": null,
        "updatedAt": "2026-05-16T09:12:00.000Z",
        "memo": "踏み切りが課題"
      }
    }
  }
}
```

- `records[athleteId][skillId]` が存在しなければ `none`（未挑戦）扱い。
- `status`：`"none" | "practicing" | "almost" | "mastered"`。
- `achievedAt`：初めて `mastered` にした日付（`YYYY-MM-DD`）。それ以外は `null`。
- 達成率・タイムラインは `records` から都度計算（派生データは保存しない）。

## 6. 技術設計（既存コードへの統合）

新ファイルは作らず、`index.html` 内に実装。既存パターンを踏襲する。

| 実装項目 | 方法 |
|---|---|
| 進捗ストア | `menuStore` と同じ形の `progressStore` オブジェクト＋`loadProgress()` / `saveProgress()` |
| 保存 | `saveEdits()` の `_saveEditsTimer` を踏襲した**デバウンス保存**（400ms）。`beforeunload` でフラッシュ |
| 4つ目タブ | HTML `#topTabs` にボタン追加 → `currentTab` 分岐 → `render()` に `renderProgress()` を追加 |
| 選手セレクター | ヘッダーに要素追加。切替で `progressStore.activeAthleteId` を更新し `render()` |
| モーダル統合 | `openSkillModal()`（行4480）のヘッダー直下にステータスUIブロックを挿入 |
| カードの表示 | `renderSkills()` / `renderTreeView()` でカードHTMLにステータス由来のclassを付与 |
| 達成率計算 | `skills` 配列と `records` から純粋関数で算出（保存しない） |
| 次に挑戦できる技 | `skill.prereqs` を走査し、全prereqが当該選手で `mastered` の技を抽出 |

- Phase 1 重要修正（`scripts/check_critical_fixes.sh` の12項目）を壊さないこと。
- localStorage 破損・容量超過時のフォールバック（try/catch）を入れる。

## 7. 無料／有料ゲーティング

- 進捗トラッキングは**有料機能**。
- 無料版：成長記録タブを開くと**アップグレード案内**を表示（機能の存在を見せて販促）。
- **30日トライアル中は全解放**。
- MVP段階（フェーズ1〜3）のゲート方式：**トライアルコード入力**で有料フラグを立てる（`localStorage` に `isPaid` 相当）。
- クライアント側判定のため技術的には回避可能だが、MVPは「正直に払う層」を見るのが目的なので許容（マーケティング企画書 §11 と同方針）。フェーズ4でサーバー認証へ。

1. **習得ステータスの段階数**：4段階（未挑戦／練習中／あと少し／習得）で良いか。3段階（未挑戦／練習中／習得）に簡素化する案もある。
