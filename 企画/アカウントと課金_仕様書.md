## 1. 目的・結論

### 監督の疑問
「AさんとBさんが同じURLから入ったらデータは同期する？ ゲームのように自分のアカウントで自分のデータを使うのでは？」

### 現状（localStorage方式）
- AさんとBさんのデータは**混ざらない**（各自の端末のブラウザに別々に保存）
- ただし「アカウント」ではない → **端末ごと・ブラウザごと**。機種変更で引き継げない、ブラウザのデータ消去で消える

### 結論（ベスト）
**Firebase でアカウント制（ログイン＋クラウド保存）にする。課金開始フェーズと同時に導入する。**

- 無料パイロット中は今のまま（localStorage・全開放）でよい
- 有料版を出すときに、アカウント＋クラウド保存へ切り替える
- これで「ゲームのように、自分のアカウントで、自分のデータを、どの端末でも、安全に」が実現する
- 同時に **30日トライアル・課金もアカウントに紐づく**（端末ではなく「人」に紐づく）

---

## 2. 全体像（3つの状態）

| 状態 | ログイン | できること |
|---|---|---|
| **無料** | 不要 | ロードマップ閲覧・動画視聴・検索・ふりがな |
| **トライアル（30日）** | アカウント登録 | 全機能（進捗トラッキング・練習プログラム・メニュー保存・編集・クラウド同期） |
| **有料** | ログイン | トライアルと同じ全機能を継続 |

- 閲覧だけならログイン不要（誰でもURLで見られる＝販促の入口）
- 「保存・記録・生成」を使う瞬間に**アカウント登録 → 自動で30日トライアル開始**

---

## 3. なぜアカウント制にするのか（結論の根拠）

1. **有料の核が「進捗トラッキング」**：記録が溜まるほど解約しにくい設計。記録が端末依存で消えると、有料の価値そのものが崩れる。
2. **データ保護**：機種変更・ブラウザ掃除でも消えない。
3. **端末引き継ぎ**：保護者がスマホでもタブレットでも同じ記録を見られる。
4. **トライアル・課金が「人」に紐づく**：localStorageだとブラウザを消すだけでトライアルがリセットできてしまう。アカウントなら防げる。
5. **1つの仕組みで4つ解決**：アカウントを入れれば「データ保護・端末引き継ぎ・トライアル管理・課金」がまとめて解決する。

→ マーケティング企画書では「アカウント＝Phase 4（後回し）」だったが、**有料版を出すなら課金開始と同時に必要**と結論を更新。

## 4. 技術方式：Firebase

- **Firebase**（Google提供のBaaS＝バックエンド代行サービス）を使う
- 自前サーバー不要。今の静的HTML（GitHub Pages）に **JavaScriptライブラリを足すだけ**で動く
- 使う機能：
  - **Firebase Authentication**：ログイン（Google / メール）
  - **Cloud Firestore**：ユーザーごとのデータをクラウド保存
- 無料枠が大きく、数千ユーザー規模までは無料〜低額で運用可能
- 静的アプリにアカウントを足す**標準的なやり方**（実績豊富）

---

## 5. データモデル（クラウド保存するもの）

ユーザー1人ごとに、Firestore に以下を保存：

```
users/{uid}
  email, createdAt
  plan: 'trial' | 'paid' | 'expired'
  trialStartAt            // トライアル開始日時
  subscription: { status, period, ... }   // 課金状態
  athletes: [...]          // 進捗トラッキングの選手
  progressRecords: {...}   // 選手×技の習得状況
  menus: [...]             // 練習メニュー
  programs: [...]          // 保存した練習プログラム
  edits: {...}             // 編集モードの変更
```

- 技データ本体（`skills` / `trainings`）はアプリに内蔵のまま（クラウド保存しない）
- クラウドに上げるのは**ユーザーが作ったデータだけ**

---

## 6. 30日無料トライアルの仕組み

- アカウント作成時に `trialStartAt = 今` を**クラウドに記録**
- アプリが「今日 − trialStartAt」を計算し、30日以内かを判定
- **クラウドに記録**されているため、ブラウザのデータ消去ではリセットできない（localStorage方式の弱点を解消）
- トライアル中：全機能開放。「無料トライアル中 あと◯日」を表示
- 30日経過：有料機能をロック → 課金案内画面

## 7. 課金（MVP → 本格）

### MVP段階（パイロット〜検証期）
- 監督が出張レッスン・請求書で集金（既存の請求チャネルに乗せる）
- 支払い確認後、**そのユーザーのアカウントを `paid` にする**
  - 方法案A：監督用の簡易管理画面で対象ユーザーを paid に切り替え（CEO推奨）
  - 方法案B：コードを渡し、ユーザーがアプリでコード入力 → paid
- Stripe等の決済インフラはまだ使わない（低コストで検証）

### 本格段階（売れる確証が出てから）
- **Stripe** で月額自動課金（¥800／¥2,000）
- Stripe Checkout/Payment Link → 決済成功 → Firebase Cloud Function が webhook を受けてアカウントを `paid` に更新 → 毎月自動

## 8. 無料／有料の機能ゲート

| 機能 | 無料 | トライアル／有料 |
|---|---|---|
| ロードマップ閲覧（リスト・ツリー） | ✅ | ✅ |
| 技・トレーニング詳細・動画 | ✅ | ✅ |
| 検索・絞り込み・ふりがな | ✅ | ✅ |
| 練習メニュー作成・保存 | ❌（体験のみ） | ✅ |
| 進捗トラッキング | ❌ | ✅ |
| 練習プログラム生成 | ❌（サンプル1つ閲覧のみ） | ✅ |
| 編集モード（カスタマイズ） | ❌ | ✅ |
| クラウド同期・端末引き継ぎ | ❌ | ✅ |

※ 無料版でどこまで「お試し」させるかの細部は §11 未決事項。

## 11. 未決事項（監督の判断が必要）

1. **ログイン方法**：CEO推奨＝**Googleログイン**（保護者はGoogleアカウント保有率が高い／パスワード管理不要／実装が簡単）。補助でメール登録。

3. **Firebaseプロジェクト**：監督のGoogleアカウント（協会用など）で作成する必要がある。作成時に一緒に進める。
4. **無料版のお試し範囲**：保存系を「完全ロック（案内のみ）」か「1つだけ味見可」か。
