## 1. 目的とゴール

初心者指導者・チームコーチが、**限られた指導者数で安全かつ効率的にタンブリング練習を回せる**よう、チーム人数と目標からサーキット練習プログラムを自動生成する。

**現場の課題**：タンブリングは補助が必要 → 指導者は物理的に1ヶ所にしか入れない → 補助に入っている間、残りの選手をどう安全に自走させるかが現場最大の悩み。本機能はこれを自動で解決する。

**狙い**：監督が現場で実践しているサーキット練習の組み立て方を、ソフトが再現する。初心者指導者でもプロの練習設計ができるようになる。

---

## 2. ユーザーストーリー

- **初心者指導者**：「15人を1人で見る。バク転を教えたいが、補助に入ると他の10人が手持ち無沙汰になる。どう組めばいいか分からない」
- **チームコーチ**：「人数も指導者数も日によって変わる。毎回ゼロから練習メニューを組むのが大変」
- **監督（出張レッスン）**：「訪問先のチームに『この人数ならこう回して』を渡せると、レッスン後のフォローになる」

## 3. 機能要件

### 3.1 入力
- **チーム人数**（必須）
- **指導者人数**（必須・既定1）
- **目標**（必須）：習得を目指す技を選ぶ（例：バク転）。※テーマ選択は §9 で検討
- **練習時間**（任意・既定30分）：ローテーション時間の自動計算に使用

### 3.2 生成ロジック（概要）
- 1グループ標準人数（既定5人）から **ステーション数** を算出
- **指導者の数だけ「補助ステーション」**を作る（＝1人1ヶ所しか入れない現実を反映）
- 残りは「**自走ステーション**」＝補助不要の体づくり・ドリル
- アルゴリズム詳細は §5

### 3.3 出力（プログラム表示）
- **ステーション一覧**（カード形式）：番号／役割（🧑‍🏫指導者つき or 自走）／タイトル／内容（技・トレーニング）／1グループの人数
- **ローテーション説明**：「1ステーション◯分 × ◯周で全員が全ステーションを通過」
- **印刷対応**（現場で紙に出して使えるよう）

### 3.4 補助ステーションの安全ロジック（本機能の核心）
- **補助が必要な技（＝目標技そのもの）は必ず「指導者ステーション」に配置**する
- **自走ステーションには補助不要のものだけ**を置く：
  - トレーニング（筋力・体幹・柔軟）＝補助不要
  - 前段階の技のうち「自分だけで安全にできるドリル」（例：ブリッジ、後方ウォークオーバー）
- ⚠️ **危険な技を自走ステーションに絶対に置かない**。そのため「自走に置いてよい技」の基準が必須（§9 未決事項）。

### 3.5 保存・連携
- 生成したプログラムを保存（複数保存可）— v1
- 各ステーションを「練習メニュー」に書き出せる — v2
- 印刷 — v1

### 3.6 スコープ外（v1では作らない）
- テーマ目標（基礎づくり等）の自動構成（v2）
- 指導者3人以上の複雑な配分最適化（v2）
- 成長記録（選手の習得状況）と連動した内容自動調整（v3）

## 5. 生成アルゴリズム（詳細）

```
generateProgram({ teamSize, instructorCount, targetSkillId, totalMinutes }):
  GROUP_SIZE = 5                                  // 1グループ標準人数（§9で確定）
  stationCount = clamp(round(teamSize / GROUP_SIZE), 2, 6)
  groupSize    = ceil(teamSize / stationCount)
  skill        = skillById[targetSkillId]

  // --- 補助ステーション（指導者数だけ）---
  spotCount = min(instructorCount, stationCount)
  stations  = []
  for i in 1..spotCount:
     stations.push({ role:'spot', title:'補助つき'+skill.name, items:[skill技] })

  // --- 自走ステーションのコンテンツプール ---
  conditioning = skill.trainings                  // 体づくり（補助不要）
  drills       = skill.prereqs.filter(自走可能な技) // 前段階ドリル（§9の基準で判定）

  selfCount = stationCount - spotCount
  // 体づくり1枠＋ドリル1枠を基本に、selfCount に応じて分割・配分
  stations += buildSelfStations(selfCount, conditioning, drills)

  rotationMinutes = floor(totalMinutes / stationCount)
  return { stations, stationCount, groupSize, rotationMinutes }
```

**エッジケース**
- `teamSize ≤ GROUP_SIZE`：サーキット不要 → 「1グループで通し練習」を提案
- `instructorCount ≥ stationCount`：全ステーションが補助つき（自走ゼロ）
- 自走コンテンツが足りない：ステーション数を減らす、または内容を合流

## 6. データモデル

新規 localStorage キー **`cheerTumblingPrograms_v1`**（保存機能用・v1後半）：

```json
{
  "version": 1,
  "programs": [
    {
      "id": "prog_xxx",
      "name": "15人バク転サーキット",
      "teamSize": 15,
      "instructorCount": 1,
      "targetSkillId": "standing-bhs",
      "totalMinutes": 30,
      "createdAt": "2026-05-17T..."
    }
  ]
}
```

- プログラムは入力値を保存し、表示時に毎回 `generateProgram()` で再生成（生成結果は保存しない＝技データ更新に自動追従）。
- 生成ロジックは既存の `skills[].trainings` / `skills[].prereqs` を参照（新データ不要）。

## 7. 無料／有料ゲーティング

- **無料**：サンプルのサーキットプログラムを1つだけ固定表示（例：15人・指導者1人・バク転）。機能の価値を見せて販促。
- **コーチプラン（有料）**：人数・指導者数・目標を入力して**自動生成し放題**＋保存・印刷。
- MVP段階のゲート方式はトライアルコード方式（マーケティング企画書 §11 と同方針）。

## 9. 未決事項（監督の判断が必要）

1. **1グループの標準人数**：既定5人でよいか。4〜6で可変にするか。
2. **自走ステーションに置いてよい技の安全基準**（最重要・安全に直結）：
   - 案A：レベル閾値（例：レベル1以下の技は自走可）
   - 案B：技データに「自走可フラグ」を新設し、監督が技ごとに指定
   - CEO推奨：案B（監督が技ごとに安全判断できる。安全機能なので明示指定が確実）
3. **配置**：新タブ「練習プログラム」（推奨）か、練習メニュータブ内の一機能か。
4. **目標の選び方**：v1は「技を選ぶ」のみでよいか。「テーマ（基礎づくり・ジャンプ強化 等）」も選べるようにするか（v2候補）。
5. **指導者2人以上**：補助ステーションを単純に増やす方式でよいか。サーキットを2系統に分ける案も将来検討。
6. **ローテーション時間**：練習時間入力からの自動計算でよいか（休憩・説明時間の控除は入れるか）。
